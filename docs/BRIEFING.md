## 1. โปรเจกต์นี้คืออะไร

เว็บขายสิทธิ์ใช้งานอินดิเคเตอร์ TradingView แบบรายเดือน/รายไตรมาส สำหรับลูกค้าไทย
ขึ้นเว็บจริงแล้วที่ **https://goldhybridshot.com** (โดเมนจดที่ GoDaddy ชี้ DNS มาที่ Render)

รายได้มาสองทาง:

1. **ลูกค้าจ่ายเงินเอง** — โอนผ่าน PromptPay QR แนบสลิป แอดมินตรวจแล้วอนุมัติ (ไม่มี payment gateway)
2. **สิทธิ์ฟรีผ่าน IB โบรกเกอร์** — ลูกค้าเปิดบัญชีเทรด XM หรือ Exness ผ่านลิงก์พาร์ทเนอร์ ฝากเงินครั้งแรกครบขั้นต่ำ แล้วยื่นเลขบัญชี MT4/MT5 ให้แอดมินตรวจใน Partner Portal อนุมัติแล้วได้สิทธิ์ **7 วัน** ต่ออายุได้เรื่อย ๆ

การเปิดสิทธิ์จริงในปลายทาง (TradingView / Discord / Telegram) **ทำด้วยมือ** เพราะ TradingView ไม่มี API ทางการ ระบบแค่บันทึกว่าช่องทางไหนเปิดให้แล้ว

## 2. สแตกและโครงสร้าง

| ส่วน | สิ่งที่ใช้ |
|---|---|
| เฟรมเวิร์ก | Next.js 15.5 App Router + React 19 + TypeScript + Tailwind |
| ฐานข้อมูล | PostgreSQL — production อยู่ที่ Neon (ap-southeast-1), dev อยู่ที่ localhost:5432 |
| ORM | Prisma 5.22 |
| ล็อกอิน | NextAuth v4 กลยุทธ์ JWT อายุ 30 วัน |
| เทสต์ | Vitest (unit + integration ที่ต่อ PostgreSQL จริง) |
| โฮสต์ | Render (Blueprint ใน `render.yaml`) |

โครงหลัก:

```
src/app/(marketing)   หน้าขายของสาธารณะ
src/app/(account)     หน้าสมาชิก
src/app/(admin)       หลังบ้าน — ทุกหน้าผ่าน requireAdminPage()
src/app/api           webhook / cron
src/lib/admin         ตรรกะหลังบ้าน (order-review, members, settings, audit)
src/lib/broker-ib     ตรรกะสิทธิ์ผ่าน IB ทั้งหมด
src/lib/jobs          งานอัตโนมัติ (expiry, watchdog)
src/config            ค่าคงที่ของธุรกิจ — ตัวเลขวันทั้งหมดต้องมาจากที่นี่
prisma/migrations     migration (เขียนมือบางไฟล์ เพราะต้องแก้ข้อมูลด้วย)
tests/                unit
tests/integration/    ต่อ PostgreSQL จริง
```

## 3. คำสั่งที่ใช้บ่อย

```bash
npx tsc --noEmit                                  # ตรวจชนิดข้อมูล
npx vitest run                                    # unit (ตอนนี้ 458 ข้อ)
npm run test:integration -- --testTimeout=30000   # integration (ตอนนี้ 208 ข้อ) ต้องมี PostgreSQL ที่เครื่อง
npm run db:up                                     # ยก PostgreSQL ด้วย docker compose
npm run db:seed
```

**เครื่องของเจ้าของโปรเจกต์หน่วยความจำตึงมาก** — ห้ามร้อย `tsc && vitest && test:integration` ต่อกันในคำสั่งเดียว จะถูกฆ่าด้วย exit 134 ให้รันทีละคำสั่ง และปิด dev server ก่อน

---

## 4. การ deploy (สำคัญมาก)

```
push ขึ้น main → GitHub Actions (.github/workflows/deploy.yml)
   → tsc + unit + integration
   → ถ้าผ่านทั้งหมด จึง curl ไปที่ Render deploy hook
```

**ทุก push ขึ้น main คือการ deploy ขึ้นเว็บจริง** ให้ถามเจ้าของก่อนเสมอ

**migration ต้องรันกับ Neon ก่อน push** ไม่ใช่หลัง — ไม่งั้นโค้ดใหม่จะเจอสคีมาเก่า เจ้าของจะรัน SQL เองใน Neon SQL Editor ให้เตรียมคำสั่งให้เขา

**เครื่อง dev ไม่มี connection string ของ production** อยู่เลย (อยู่แต่ใน Render/Neon) ถ้าจะตอบคำถามเกี่ยวกับข้อมูลจริง ห้ามเดาจาก `.env` ในเครื่อง เพราะนั่นคือฐานข้อมูล localhost คนละตัวกัน — เคยพลาดมาแล้ว

## 5. กติกาที่ห้ามละเมิด (ย่อจาก CLAUDE.md)

1. **ทุกฟีเจอร์ต้องมีเทสต์** เรื่องเงินและสิทธิ์ต้องเป็น integration test กับ PostgreSQL จริง ห้าม mock
2. **ห้ามบอกว่าเสร็จถ้ายังไม่ได้รันจริง** ต้องมีหลักฐาน
3. **commit เฉพาะไฟล์ที่แก้จริง** ห้าม `git add -A` / `git add .`
4. **ห้ามรีวิวปลอม / สถิติกำไรปลอม** ผิดกฎหมายคุ้มครองผู้บริโภคไทย
5. **ความลับอยู่ใน `.env` เท่านั้น** ห้ามพิมพ์ token / secret / DB URI ลงโค้ด เทอร์มินัล หรือ commit
6. **ห้ามล้มเงียบ** ทุกงานอัตโนมัติต้อง log + แจ้งกลุ่มแอดมินทาง Telegram เมื่อพัง
7. **ทุก action ของแอดมินที่มีผลจริงต้องมี lock กันกดซ้ำ และเขียน Audit Log** (ใคร เมื่อไร ก่อน-หลัง IP)
8. **ไฟล์ `.ps1` ต้องเป็น UTF-8 with BOM** และรูปภาพต้องใช้ `next/image` พร้อม `sizes`
9. **จบทุกเซสชันต้องอัปเดต `docs/HANDOFF.md`**

## 6. จุดที่พลาดง่าย (อ่านก่อนแก้โค้ด)

### ตัวเลขวันห้ามเขียนตายตัว
มีเทสต์ `tests/day-counts-from-config.test.ts` เดินอ่านทุกไฟล์ `.ts/.tsx` นอก `src/config` แล้ว**ล้มทันทีถ้าเจอ `\d+ วัน` ที่พิมพ์ตายตัว** ต้องอ้างจาก `BROKER_IB_PLAN.durationDays` / `PAYMENT_RULES.expiryReminderDays` เสมอ
เทสต์นี้เกิดจากของจริงที่เคยพลาด — เคยลดสิทธิ์ IB จาก 30 วันเหลือ 7 วัน แต่คำโฆษณาบนหน้าเว็บยังเขียน 30 วันอยู่ กลายเป็นสัญญาเกินจริงสี่เท่าบนเว็บจริง

### ระยะเวลาแพ็กเกจอ่านจากฐานข้อมูล ไม่ใช่จาก config
`createBrokerClaim` อ่าน `durationDays` จากแถว `Plan` ในฐานข้อมูล **การแก้ `src/config/broker-ib.ts` อย่างเดียวจึงไม่เปลี่ยนพฤติกรรมจริง** ต้องเขียน migration แก้แถวนั้นด้วย

### หน้าต่างต่ออายุต้องสั้นกว่าอายุสิทธิ์
`BROKER_IB_RULES.renewalWindowDays` (2) ต้องน้อยกว่า `durationDays` (7) เสมอ ถ้าเท่ากันเมื่อไร สมาชิกจะยื่นต่อซ้ำได้ทันทีหลังอนุมัติ = ได้สิทธิ์ฟรีไม่รู้จบจากการฝากเงินครั้งเดียว มีเทสต์ดักไว้แล้ว

### JWT เก็บ role ไว้ 30 วัน
`src/middleware.ts` อ่าน `token.role` จาก JWT ซึ่งไม่รีเฟรช ผลคือ:
- **ลดสิทธิ์มีผลทันที** เพราะ `requireAdminPage()` และ `getAdminActor()` อ่าน role จากฐานข้อมูลใหม่ทุกครั้ง middleware เป็นแค่ด่านแรก
- **เลื่อนขั้นเป็นแอดมินไม่มีผลทันที** ต้องให้เจ้าตัวออกจากระบบแล้วเข้าใหม่หนึ่งครั้ง

### AuditLog เป็น append-only จริง ๆ
มี trigger ที่ฐานข้อมูลห้ามแก้และห้ามลบ และ `actorId` เป็น `onDelete: Restrict` **ลบผู้ใช้ที่เคยทำ action หลังบ้านไม่ได้** ให้ลดสิทธิ์และปิดการใช้รหัสผ่านแทน

### ยอดฝากขั้นต่ำ IB เก็บเป็น "บาท" แต่ข้อตกลงเป็น "USD"
ระบบเก็บ `ibMinDepositXmThb` / `ibMinDepositExnessThb` แล้วแปลงเป็น USD ด้วย `ibUsdThbRate` ที่แอดมินตั้งไว้ **ถ้าแก้อัตราแลกเปลี่ยนโดยไม่แก้ยอดบาททั้งสองช่องตาม ขั้นต่ำจริงจะเพี้ยนทันที** มีเทสต์ `tests/integration/broker-ib-fifty-usd.test.ts` ยึดผลลัพธ์ปลายทางไว้แล้ว

## 7. สถานะตอนนี้

### ทำเสร็จและขึ้นเว็บจริงแล้ว
- วงจรซื้อ-อนุมัติ-ต่ออายุทบวัน-คืนเงิน-ปิดสิทธิ์ ครบและผ่าน UAT ทั้งเส้นทาง
- เส้นทาง IB ครบ ทั้งยื่น อนุมัติ ปฏิเสธ ต่ออายุ ปิดสิทธิ์ และนำเข้ารายงานโบรกเกอร์เพื่ออนุมัติอัตโนมัติ
- ป้องกันสลิปซ้ำด้วย hash และกันอนุมัติซ้อนด้วย advisory lock
- บอท Telegram แจ้งเตือนสมาชิกก่อนหมดอายุ (แชตส่วนตัว ไม่ใช่กลุ่ม) + watchdog รายชั่วโมง
- **กำหนดสิทธิ์แอดมินจากหน้า `/admin/members/[id]`** เปลี่ยนสิทธิ์ตัวเองไม่ได้ ลดแอดมินคนสุดท้ายไม่ได้ ตรวจซ้ำใต้ล็อกว่าผู้สั่งยังเป็นแอดมิน และแจ้งกลุ่มแอดมินทุกครั้ง
- บันทึกทุกครั้งที่คำสั่งหลังบ้าน**ถูกปฏิเสธ** (`ADMIN_ACTION_REFUSED`) เพื่อไล่เคส "กดแล้วไม่เข้า" ได้

### ค้างอยู่ — ต้องให้เจ้าของทำเอง (เป็นการตั้งค่า ไม่ใช่โค้ด)

| สิ่งที่ต้องทำ | ตั้งที่ไหน | ถ้าไม่ทำจะเป็นอย่างไร |
|---|---|---|
| ยอดฝากขั้นต่ำ XM และ Exness ให้เท่ากัน = 50 USD (เช่น อัตรา 33.5 → กรอก 1675 ทั้งสองช่อง พร้อมตั้งอัตราในช่องเดียวกัน) | `/admin/settings` | ตอนนี้ยังเป็น 1,000 บาท (XM) และ 1,500 บาท (Exness) = ต่ำกว่าที่ตกลงกับพาร์ทเนอร์ ลูกค้าฝากน้อยกว่าที่ตกลงแล้วได้สิทธิ์ฟรี |
| `NEXT_PUBLIC_LEGAL_OPERATOR_NAME` และ `NEXT_PUBLIC_LEGAL_OPERATOR_ADDRESS` | Render | ข้อกำหนดการใช้บริการยังขึ้นว่า "[รอระบุโดยผู้ให้บริการ]" ซึ่งขายของจริงไม่ได้ตามกฎหมาย |
| `secrets.BACKUP_DATABASE_URL` และ `vars.BACKUP_GPG_PUBLIC_KEY` | GitHub | งานสำรองฐานข้อมูลรายคืนจะล้มทุกคืน (หรือปิด schedule ไปก่อน) |

### กับดักที่ต้องจำ
หลัง **19 พฤศจิกายน 2569** โปรเจกต์เก่าบน Vercel ที่หยุดไว้จะกลับมาทำงาน และ cron ของมันจะยิงเข้าฐานข้อมูล Neon ตัวเดียวกันกับ production — **ต้องลบหรือชี้ไปที่อื่นก่อนวันนั้น**

## 8. วิธีทำงานกับเจ้าของโปรเจกต์

- เขาสื่อสารภาษาไทย ให้ตอบภาษาไทย และเขียนคอมเมนต์ในโค้ดเป็นภาษาไทยตามของเดิม
- เขาต้องการ**ความตรงไปตรงมา** ถ้าทำไม่ได้หรือยังไม่ได้ตรวจ ให้บอกตรง ๆ อย่าเคลมว่าเสร็จ
- เขาอนุมัติทีละขั้น ให้ถามก่อน push และก่อนทำอะไรที่ย้อนกลับยาก
- งานที่ต้องเข้าหน้า `/admin` ของเว็บจริง เขาเป็นคนล็อกอินเอง (AI ไม่ควรกรอกรหัสผ่านบัญชีจริง) แล้วค่อยให้ agent กรอกฟอร์มต่อ
